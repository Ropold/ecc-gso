## Betriebliche Tätigkeiten:

### XRechnung – Fehleranalyse beim E-Mail-Versand
- Festgestellt, dass aus einer gebuchten Verkaufsrechnung keine E-Mail verschickt werden kann
- Herausgefunden, dass nicht die XRechnung das Problem ist, sondern die E-Mail-Einrichtung in Navision nicht funktioniert

### Server – Datenbanken und Speicherplatz
- Aufräumarbeiten auf den EC-Consulting-Servern weitergeführt
- Einrichtung von Kunden-Navision-Umgebungen auf dem Testserver:
  - Datenbank kopieren
  - Datenbank mit SSMS (SQL Server Management Studio) in MS SQL Server 2022 einhängen
  - Richtige Navision-/BC-Version herausfinden
  - Navision-/BC-DVD herunterladen
  - Dienst-Ordner von der DVD kopieren
  - Skript zum Anlegen des Dienstes ausführen und Parameter anpassen
  - Client von der DVD kopieren, bei BC zusätzlich das Webclient-Skript für die Installation ausführen
  - Admin-Benutzer mit SUPER-Rechten anlegen, entweder per Skript oder per Insert in SSMS
  - Ggf. Lizenz einspielen

### Artikelbemerkungen im Verkauf
- Anzeige der Artikelbemerkungen aus der Artikelkarte mit dem Code „AR“ als Popup im Verkaufsauftrag und im Verkaufsangebot integriert
- Die Umsetzung entspricht der bestehenden Logik im Einkauf
- Logik in der „Sales Order Subform“ und der „Sales Quote Subform“ über den Trigger „OnAfterValidate“ des Feldes „No.“ implementiert
- Neue Page „CommentItemAR“ für die Anzeige der Bemerkungen erstellt

### Anpassung der Verkaufsbelege – EORI und USt-ID
- Folgende Reports angepasst:
  - Verkaufsauftrag, gebuchte Verkaufsrechnung,gebuchte Verkaufslieferung, gebuchte Verkaufsgutschrift
- Die Werte EORI und USt-ID des Kunden werden in der jeweiligen Debitorenkarte im Reiter „Fakturierung“ gepflegt und an die Reports übergeben
- Die EORI der eigenen Firma im Footer wird aus der Page „Firmendaten“ übernommen und an die Reports übergeben
- Im Report „Gebuchte Verkaufsrechnung“ zusätzlich „ein Wort“ an drei Stellen fett formatiert, wie bereits in den anderen Belegen
 - Dafür wurde die Textvariable in „Bold“ und „Rest“ aufgeteilt, damit die Fettformatierung im Layout umgesetzt werden konnte
- Überschriften in Englisch und Deutsch gemäß den Vorgaben aus dem SAF angepasst

### Löschen von Einkaufsbestellungen im Livesystem
- Drei Einkaufsbestellungen sollten im Livesystem gelöscht werden
- Festgestellt, dass die Bestellungen nicht gelöscht werden konnten, da sie noch mit Wareneingangszeilen verknüpft waren
- Die verknüpften Wareneingangszeilen gelöscht und anschließend die Bestellungen gelöscht

### Neueinrichtung einer BC28-Umgebung auf einem Kundenserver
- Zugang beim Server-Dienstleister des Kunden angefragt und erhalten
- SQL Server 2022 und SSMS (SQL Server Management Studio) installiert
- ServiceTierAdministration-Tool installiert
- Datenbank kopiert und in SQL Server 2022 eingehängt
- Wiederherstellungsmodell der Datenbank von „Vollständig“ auf „Einfach“ gesetzt, da es sich um eine temporäre Upgrade-Instanz von BC25 auf BC28 handelt
  - Dies ist der erste Testdurchlauf; das eigentliche Upgrade mit der Live-Datenbank wird zu einem späteren Zeitpunkt durchgeführt
- Dienst und Webclient für BC28 installiert
- Lizenz eingespielt
- ForNAV – Fehlerbehebung in der Testumgebung:
  - Neueste Direct-Print-Versionen „ReportsForNAV_8_3_0_2873“ und „CustomizableReportPack_BC28.0_8_3_2800_1“ in BC28 installiert
  - Fehler bei der Einbindung von Direct Print über die „ForNAV Direct Print Security Keys“ behoben, sodass der Status „Waiting“ korrekt angezeigt wird
  - Festgestellt, dass sich der Report „Verkaufsangebot“ nicht öffnen ließ, da noch auf das alte Layout der Version 7.0.0.2371 zugegriffen wurde
  - Unser Testsystem auf die gleiche ForNAV-Version aktualisiert, den Report „Verkaufsangebot“ auf das neue Layout der Version 8.3 umgestellt und die neue App-Version in das Testsystem eingespielt
